# C0 스파이크 계획 — 코어 모드 골격과 기술 불확실성 해소

> 대상: `server-core-mod-spec.md` 5장의 C0, `combat-spec.md` CB0, `gearbridge-spec.md` GB0, `fx-spec.md` FX0의 **선행 확인 사항**.
> 상태: **계획** + 골격 초안(`economycore/`, **미컴파일**). 스파이크 결과는 `docs/c0-spike-results.md`(11장 템플릿)에 기록한다.
> 원칙: **코드를 많이 쓰는 것이 목적이 아니라, 설계 문서가 가정한 것을 실제 NeoForge 1.21.1에서 확인**하는 것이다. 가정이 틀리면 설계 문서를 먼저 고친다.

## 1. 목적과 범위

**C0의 답을 얻어야 하는 질문(우선순위 순)**

| # | 질문 | 영향받는 문서 | 틀릴 때의 대안 |
|---|---|---|---|

| Q7 | 일반 유저의 **아이템 생성 명령·크리에이티브**를 차단할 수 있는가? | 2.4 | 권한 레벨 설정, 명령 이벤트 취소 |
| Q8 | 코어 발급 장비에 **무적(unbreakable)** 이 적용되고, 타 모드 도구의 내구도 감소를 막을 수 있는가? | 2.3 | 이벤트/믹스인 |
| Q9 | **SQLite(JDBC)** 를 모드에 포함(jar-in-jar)해 쓸 수 있고 비동기 큐·outbox 골격이 가능한가? | `persistence`, 명세 14.2 | PostgreSQL 전용, 외부 DB |

## 3. 프로젝트 골격 (`economycore/`)

이 저장소에 **미컴파일 초안**을 추가했다(`economycore/README.md` 참고). 구성은 다음과 같다.

| 파일 | 역할 | 해당 스파이크 |
|---|---|---|
| `build.gradle`·`settings.gradle`·`gradle.properties` | ModDev 플러그인, 실행 구성(client/client2/server) | S0 |
| `neoforge.mods.toml` | 모드 선언, TaCZ 선택 의존 | S0·S11 |
| `EconomyCore.java` | 진입점: 등록·이벤트 연결 | S0 |
| `item/GearItem`·`ModItems` | 신규 근접 무기 아이템(SwordItem 비상속) | S3·S4 |
| `component/GearData`·`ModComponents` | `economycore:gear` 컴포넌트(Codec+StreamCodec) | S3 |
| `net/AttackIntentPayload` | 공격 의도 패킷(action, seq만 전송) | S4 |
| `client/ClientInput` | `GearItem`을 든 상태의 클릭을 의도 패킷으로 대체 | S4·S13 |
| `guard/RecipeGuard` | 레시피 필터 스텁 | S1 |
| `command/EconomyCommands`·`config/ConfigService` | `/economycore reload\|status`, JSON 설정 | S10 |

골격의 NeoForge API 이름(`DeferredRegister.createDataComponents`, `InputEvent.InteractionKeyMappingTriggered`, `registrar.playToServer` 등)은 **컴파일로 확인**해야 하며, 틀린 이름은 결과 문서에 기록하고 바로잡는다.

## 4. 스파이크 항목

각 항목은 **질문 → 접근 → 절차 → 합격 기준 → 산출물** 순이다. 우선순위: **P0**(설계를 좌우) / **P1**(중요하지만 대안 있음).

### S0. 빌드·기동 (P0, 0.5일) — Q12 일부
- **절차:** `./gradlew build` → `runServer` 기동 → 로그에 `[economycore] loaded` → `runClient` 접속 → `/economycore status`.
- **합격:** 서버·클라이언트 모두 오류 없이 기동하고 명령이 동작. **전용 서버 로그에 클라이언트 전용 클래스 로딩 오류 없음**(`ClientInput`가 서버에서 로드되지 않음).
- **산출물:** 컴파일 가능한 골격, 정정된 API 목록.

### S1. 레시피 필터 (P0, 1일) — Q1
- **접근 후보:** (a) 서버 시작 후 `RecipeManager`의 레시피 목록을 필터해 교체, (b) 리로드 리스너로 `/reload`에도 재적용, (c) 필요하면 믹스인으로 `RecipeManager` 적용 시점을 후킹.
- **절차:** ① `economycore-guard.json`의 `log_only`로 **전체 레시피 수·네임스페이스별 분포·레시피 타입 분포**를 로그로 출력(바닐라+FD/KC+LR+TaCZ+가구 모드 설치) ② `enforce`로 허용 네임스페이스 밖 제거 ③ `/reload` 후 재적용 확인 ④ 클라이언트(JEI 등)에 보이는 레시피와의 동기화 확인 ⑤ 런타임에 생성되는 레시피(호환 모드 등) 존재 여부.
- **합격:** 제거 대상 레시피로 **어떤 제작대에서도 결과물을 만들 수 없음**(수동 제작 시험), `/reload` 후에도 유지, 허용 목록의 레시피는 유지.
- **산출물:** 적용 훅 시점과 방식(믹스인 필요 여부), 서버·클라이언트 불일치 처리 방안. → `server-core-mod-spec` 2.1과 6장 미확정 4번 갱신.

### S2. 결과 슬롯·작업대 우회 (P0, 1일) — Q2
- **접근:** NeoForge 이벤트(제작/화로 수령, 모루·숫돌 결과 이벤트 등)의 커버리지를 표로 만들고, 이벤트로 못 막는 곳은 메뉴/슬롯 후킹이 필요한지 판단.
- **절차:** 대상 표 작성 → 각 경로에서 제한 아이템을 얻으려 시도: 2×2/3×3 제작, 화로·훈연기·용광로, 석재 절단기, 대장간, 모루, 숫돌, 마법 부여대, 주민 거래, 조리 블록(FD/KC), 호퍼·디스펜서 자동화.
- **합격:** 전 경로에서 제한 대상이 지급되지 않거나 서버가 결과를 회수·거부하고 `CRAFT_DENIED`가 기록됨. 막을 수 없는 경로는 **목록화**.
- **산출물:** 경로별 차단 가능 여부 표(→ G1 체크리스트 X2·X5·X6).

### S3. 신규 아이템·컴포넌트·모델 (P0, 1일) — Q3
- **절차:** ① `GearItem` 등록·`/give`로 지급 ② 컴포넌트(`economycore:gear`) 값을 설정해 월드 저장→재접속→서버 재시작 후 유지 ③ 클라이언트로 동기화(툴팁에 `def_id` 표시) ④ **다른 `def_id`마다 다른 모델**: `custom_model_data` 컴포넌트 predicate + 리소스 모델 JSON(코드 변경 없이 추가 가능한지) ⑤ LR `CUSTOM_DATA`와 공존 시험(LR 설치 시 충돌 없음).
- **합격:** 위 5개 모두 통과. `def_id` 추가 = 리소스 + 데이터만으로 가능한지 결론.
- **산출물:** 모델 변형 방식 결정(`combat-spec` 11장 7번 확정/수정), `GearData` 직렬화 확정.

### S4. 의도 패킷·바닐라 공격 차단 (P0, 1.5일) — Q4
- **절차:** ① 클라이언트: `GearItem` 보유 시 좌/우 클릭을 취소하고 의도 패킷 전송, 스윙 연출 처리 방식 선택 ② 서버: 수신 핸들러(순번 단조 증가·레이트 제한·메인핸드 확인) ③ 바닐라 공격 이벤트·블록 좌클릭·휩쓸기·기본 공격 쿨다운 UI가 발생하지 않는지 ④ 우클릭 사용(`Use`)과 분리 ⑤ 입력이 취소돼도 다른 모드 키(예: TaCZ)와 충돌하지 않는지.
- **합격:** 몹을 때려도 바닐라 피해가 발생하지 않고(서버 로그), 의도 패킷만 서버에 도착. 패킷 위조(초당 수백 개)가 레이트 제한에 걸림.
- **산출물:** 입력 처리 설계(이벤트 취소 이중화 필요 여부), 공격 쿨다운 HUD 연결 지점.

### S5. 서버 범위 판정 프로토타입 (P0, 1.5일) — Q5
- **절차:** 의도 패킷 수신 → `delay` 틱 예약 → **서버의 눈 위치·시선**으로 원뿔 필터(반경·반각) → 대상 정렬·상한 → 바닐라 `hurt` 경로로 피해 적용(방어구 감소 확인) → 무적 시간 임계 처리 → LOS 레이캐스트(벽 차폐).
- **합격:** 원뿔 밖·벽 뒤 대상은 맞지 않음, 방어구가 피해를 줄임, 콤보 간 무적 시간 설정이 동작, 20명 동시 공격 시 틱 시간 증가가 허용 범위(예: 틱당 < 2ms 추가).
- **산출물:** 판정 함수 시그니처(재사용용, `fx`의 호 기하와 공유), 성능 측정값.

### S6. 이펙트 전송·자체 파티클 (P1, 1일) — Q6
- **절차:** ① 서버가 바닐라 파티클·소리를 반경 N블록에 전송 ② 자체 파티클 타입 1개 등록(텍스처 jar 포함) ③ 호(arc) 좌표 계산 후 파티클 N개 전송 ④ 예산 카운터(플레이어당/서버 초당) 구현 및 초과 시 축소.
- **합격:** 모드팩 일치 클라이언트에서 자체 파티클이 보이고, 예산 초과 시 우선순위대로 생략되며, 20명 동시 연출에서 서버 TPS 유지.
- **산출물:** 파티클 전송 API 선택, 예산 기본값 초기 실측.

### S7. 명령·크리에이티브 통제 (P1, 0.5일) — Q7
- **절차:** 일반 유저(권한 0)가 `/give`·`/summon`·`/setblock`·게임모드 변경을 시도 → 차단 이벤트·권한 설정으로 막기, 관리자 명령은 `admin_audit` 로깅 지점 확인.
- **합격:** 일반 유저는 아이템 생성 경로 없음, 관리자 행위는 기록.
- **산출물:** `guard.command` 정책 방식(권한 레벨 vs 이벤트 취소).

### S8. 내구도 (P1, 0.5일) — Q8
- **절차:** `GearItem`은 damageable이 아님을 확인, 코어가 발급하는 타 모드/바닐라 도구에 `unbreakable` 컴포넌트를 붙여 사용 → 내구도 감소 없음, 컴포넌트를 무시하는 타 모드 도구가 있는지 표본 시험(FD 식칼, Aquaculture 낚싯대 등).
- **합격:** 대표 도구 5종에서 내구도 감소 없음, 무시하는 도구는 목록화.
- **산출물:** `guard.durability` 보조 훅 필요 여부.

### S9. 영속화 골격 (P1, 1일) — Q9
- **절차:** SQLite JDBC를 jar-in-jar로 포함해 서버에서 로드되는지 확인(서비스 로더·드라이버 등록 문제), 비동기 쓰기 큐, `event_id UNIQUE` 멱등 삽입, **outbox 재실행 골격**(커밋 후 강제 종료 → 재기동 시 1회 적용), 월드 저장과의 경계.
- **합격:** 강제 종료(kill -9) 후에도 중복 지급 없이 재처리.
- **산출물:** DB 접근 계층 인터페이스, SQLite→PostgreSQL 전환 가능성 평가.

### S10. 설정·핫리로드 (P1, 0.5일) — Q10
- **절차:** `config/economycore/*.json` 로드, 잘못된 JSON은 로드 거부 + 로그, `/economycore reload`로 반영(레시피 필터 재적용 포함).
- **합격:** 서버 재시작 없이 설정이 바뀌고 잘못된 설정이 기존 값을 깨지 않음.

### S11. lockcheck (P1, 0.5일) — Q10
- **절차:** 로드된 모드 목록·버전·jar 해시를 읽어 `locklist`와 대조(불일치 시 경고/거부).
- **합격:** 모드 1개를 바꾸면 불일치가 보고됨.

### S12. TaCZ·LR 공존 (P0, 1일) — Q11
- **절차:** 서버에 TaCZ 1.2.0 + LR(1.21.1 브랜치 빌드) + economycore 동시 기동 → 로드 순서·오류 확인 → S1 필터로 LR 근접 제작법(`recipe/melee`)·대장간 블록 결과 차단 확인 → 총기 발사/피격이 우리 `combat`과 충돌하지 않는지 → **코어가 TaCZ/LR 클래스에 컴파일 의존하지 않고** 동작함을 확인.
- **합격:** 세 모드가 같이 기동, LR 근접 레시피가 막힘, 총기 사용에 영향 없음.
- **산출물:** G1 체크리스트의 공존 항목 일부 완료, 의존 방식 결론(선택 의존 + 이벤트/데이터).

### S13. Dist 분리 (P1, 0.5일) — Q12
- **절차:** 전용 서버에서 클라이언트 클래스(`ClientInput` 등)가 로딩되지 않는지 확인(`@EventBusSubscriber(value = Dist.CLIENT)`), 서버/클라이언트 모드 불일치 접속 거부 동작 확인.
- **합격:** 전용 서버 기동 로그에 클라이언트 클래스 오류 없음.
