# 모션 제작 가이드 (Claude 작업용 지식 문서) v0.1

> 용도: 로컬 PC에서 Claude Code를 쓸 때, 매 세션 시작 시 이 문서를 읽혀서 **무기 모션 제작 방식·규칙·검증 절차**를 일관되게 적용하게 한다. (Claude는 세션 간 기억이 없으므로 이 문서와 아래 "발견 기록"이 기억을 대신한다.)
> 사용법: 저장소 루트의 `CLAUDE.md`에 `@docs/motion-authoring-guide.md`로 참조하거나, 스킬로 등록한다.
> 상태: **형식 세부는 아직 실제 파일로 확인하지 않았다.** `[확인 필요]` 표시는 파일 분석 후 채운다.

## 1. 작업 원칙

- 사람이 최종 승인한다. Claude는 직접 재생해 "자연스럽다"를 판정하지 않는다. **구조 오류를 잡고, 후보를 만들고, 검수 자료를 준비**한다.
- 사람이 만든 **유형별 기본 모션(아키타입 베이스)** 만 수작업으로 만들고, 개별 무기는 그 위의 **파라미터와 연출 데이터**로 변형한다.
- 한 번에 많이 만들지 않는다: 아키타입 1개 → 검증 → 승인 → 잠금 → 다음.
- 모르는 것은 추측하지 않고 `[확인 필요]`로 표시하고 실제 파일로 확인한다.

## 2. 아키타입 체계 (제안)

| 아키타입 | 특징 | 기본 모션 세트 |
|---|---|---|
| 한손검 | 중간 속도, 직선/사선 베기 | 대기, 꺼내기, 공격 콤보, 점검, 집어넣기 |
| 대검 | 느린 준비, 큰 호, 무거운 복귀 | 동일 + 차지 공격 [제안] |
| 단검 | 빠른 연타, 짧은 호 | 동일 |
| 창 | 찌르기 중심, 긴 사거리 | 동일 |
| 쌍검 | 양손 교차 | 동일 + 좌우 번갈아 |
| 도끼 | 내려치기, 중량감 | 동일 |

- 아키타입 수는 10개 안팎으로 제한(사람이 직접 만들 수 있는 규모).
- 기본 모션 세트의 필수 구성: `idle`, `draw`, `attack_1..N`, `inspect`, `put_away` + (해당 시) `walk/run` 보정 `[확인 필요: 실제로 필요한 종류는 모드 포맷 분석 후 확정]`.

## 3. 모션 설계 어휘 (사람의 움직임을 키프레임으로 바꾸는 규칙)

### 3.1 공격 모션 단계

```text
예비동작(anticipation) → 가속 → 타격 프레임(impact) → 후속동작(follow-through) → 복귀(recovery) → 대기
```

- **타격 프레임**: 서버 판정이 일어나는 순간과 맞춘다. 판정 시점은 모션 데이터에 명시한다(`hit_frame_ms`).
- 무게감 = 예비동작 길이 + 복귀 길이 + 이징 곡선. 무거운 무기일수록 예비동작과 복귀가 길고, 타격 직전 가속이 급하다.
- 호(arc): 팔과 무기 끝이 그리는 궤적은 직선이 아니라 곡선이 되도록 중간 키프레임을 둔다.
- 겹침(overlap): 손 → 무기 → 몸 순으로 시간차를 둬서 뻣뻣함을 줄인다.

### 3.2 파라미터 (개별 무기가 바꿀 수 있는 값)

```yaml
weapon_motion:
  id: "sword_iron_01"
  archetype: "one_hand_sword"
  provenance: "original"
  timing:
    anticipation_ms: 120
    strike_ms: 90
    recovery_ms: 220
    hit_frame_ms: 150
  arc:
    start_angle_deg: -40
    end_angle_deg: 70
    amplitude: 1.0          # 호 크기 배율
  easing: { anticipation: "ease_out", strike: "ease_in", recovery: "ease_in_out" }
  mirror: false
  combo_order: [1, 2, 3]
  fx: { swing_sound: "...", trail_color: "#...", hit_particle: "...", hit_stop_ms: 40, camera_shake: 0.2 }
```

- 수치는 [제안]이며 첫 아키타입 제작 때 사람과 조정한다.
- 판정 타이밍을 바꾸면 DPS가 달라진다. 모션 길이를 바꿀 때는 **공격 속도(서버 값)와의 관계**를 문서화한다. `[확인 필요: 판정이 애니메이션과 독립인지]`

### 3.3 연출 차별화 (모션 파일을 건드리지 않는 방법, 우선 사용)

소리, 궤적(트레일) 색·모양, 타격 파티클, 히트스톱, 화면 흔들림, 꺼내기·점검 효과, 강화 단계 오라. TaCZ 에셋을 수정하지 않고 **우리 에셋만 추가**하므로 라이선스상 안전하다.

### 3.4 티어별 투자

| 등급 | 모션 |
|---|---|
| 일반 | 아키타입 공용 + 연출 차별화 |
| 희귀 | 파라미터 변형·콤보 구성 변경 |
| 영웅/진화 최종/보스 | 수작업 고유 모션(꺼내기·점검·마무리 우선) |

## 4. 작업 절차

```text
1. 설계: 아키타입 파라미터 정의 (이 문서 3.2)
2. 베이스 제작: 사람이 Blockbench에서 기본 모션 제작 (원본 .bbmodel 보관 = 소스)
3. 변형 생성: Claude가 파라미터로 개별 무기 모션 데이터 생성 (provenance: original)
4. 자동 검증: 검증 스크립트 실행 (5장)
5. 미리보기: 미리보기 뷰어로 프레임 캡처 → Claude가 구조 오류 점검
6. 사람 검수: Blockbench/게임에서 재생해 승인 또는 수정 지시
7. 잠금: 승인된 버전 해시를 `motion_manifest`에 기록
```

- 파일 배치(제안): `assets-src/` (Blockbench 원본) / `assets/motions/` (내보낸 데이터) / `tools/` (생성·검증·미리보기) / `docs/` (이 문서, 발견 기록).

## 5. 자동 검증 항목

- [ ] 모든 키프레임의 뼈 이름이 모델에 존재
- [ ] 시간값이 오름차순이고 총 길이가 `timing` 합과 일치
- [ ] 루프 모션(`idle`)의 시작·끝 자세가 연속
- [ ] 타격 프레임이 `hit_frame_ms`와 일치하고 서버 판정 값과 일관
- [ ] 보간 방식·단위(도/라디안, 블록/픽셀)가 포맷 규칙과 일치 `[확인 필요]`
- [ ] 효과 이벤트(소리/파티클)가 모션 길이 안에 있음
- [ ] `provenance` 필드 존재, `licensed`이면 근거 링크 존재
- [ ] 좌우 반전 시 대칭 뼈 매핑 정상
- [ ] 아키타입 내 무기 간 길이·타격 프레임 편차가 허용 범위 안

## 6. 미리보기·확인 방법

- **A. 웹 뷰어**: 애니메이션 JSON을 3D로 재생하는 뷰어를 `tools/preview/`에 만들고, 헤드리스 브라우저로 프레임을 캡처해 Claude가 확인한다(손이 모델을 뚫는지, 뼈 이름 오류, 타이밍 어긋남 같은 구조 오류용).
- **B. 게임 실행**: 로컬 PC에서 개발용 클라이언트(`runClient`)를 실행해 화면 캡처로 확인. 판정과의 동기화는 이 방식으로 확인한다.
- 한계: 프레임 이미지로는 무게감·맛은 판단하기 어렵다. 최종 판단은 사람이 한다.

## 8. 새 세션 시작 체크리스트 (Claude용)

1. 이 문서와 7장 발견 기록을 읽는다.
2. 0장 금지 사항을 먼저 적용한다(TaCZ/LR 에셋 복사·변형 금지, provenance 기록).
3. 작업 대상 아키타입의 `motion_manifest` 상태(잠금 여부)를 확인한다.
4. 변경 후 5장 검증을 실행하고 결과를 요약한다.
5. 새로 알게 된 사실은 7장에 날짜와 함께 추가한다.
