## 1. 모델 요구

### 1.1 공통 규격

| 항목 | 요구(제안) |
|---|---|
| 형식 | Java 아이템 모델(JSON) + 텍스처 PNG. Blockbench로 제작, 소스(`.bbmodel`) 보관 |
| 표시 변환 | `firstperson_righthand`, `thirdperson_righthand`, `gui`, `ground`, `fixed`, `head` 변환을 모델마다 정의(대형 무기는 별도 보정) |
| 텍스처 해상도 | 32×32(기본), 대형(대검·창)은 64×32 허용. 픽셀 밀도를 무기 간 통일 |
| 모델 변형 | `custom_model_data` 컴포넌트 predicate로 `def_id`별 모델 선택(`combat-spec.md` 11장 7번). 정의 추가 = 리소스 + 데이터 |
| 이름 규칙 | 모델 `assets/economycore/models/item/gear/<archetype>/<theme>.json`, 텍스처 `assets/economycore/textures/item/gear/<archetype>/<theme>.png` |
| 파일 메타 | 각 모델 옆 `provenance` 기록(자체 제작/허락 근거), 제작자, 날짜 |
| 성능 | 모델 큐브 수 상한(예: 64개 이하), 투명 텍스처 최소화 |
| 가독성 | 아키타입 **실루엣만으로 구분**되고, 색에만 의존하지 않는다(접근성) |

### 1.2 시작 무기 목제 6종 (P0)

공통: 연습용 목검 같은 **나무 소재**(밝은 나무 + 가죽 감김 손잡이), 낮은 채도, 테마 `wood`. 티어가 올라가도 같은 모델을 쓰고 텍스처만 바꾸는 확장(4장)을 염두에 두고 **실루엣을 기준 형태로** 만든다.

| ID | 무기 | 실루엣·치수(제안) | 손잡이/특징 | 표시 변환 메모 |
|---|---|---|---|---|
| M-W01 | 목제 한손검 | 길이 약 3.5블록 높이, 직선 양날, 십자 가드 | 가죽 감김 | 표준 기준 모델 |
| M-W02 | 목제 단검 | 길이 약 2.0, 짧고 폭 좁음, 작은 가드 | 역수 쥠 형태 | 1인칭에서 낮게, 작은 크기 |
| M-W03 | 목제 쌍검 | 두 자루가 **X자로 교차**하는 한 모델(1세트=아이템 1개, `combat-spec.md` 12장) | 두 손잡이 | 1인칭에서 양쪽이 보이게 배치, 3인칭 보조 렌더는 후순위 |
| M-W04 | 목제 대검 | 길이 약 5.0, 폭 넓은 대형 날, 두꺼운 가드 | 양손 느낌의 긴 손잡이 | 등 쪽 `head`/`ground` 변환 보정 필요 |
| M-W05 | 목제 창 | 총길이 약 6.0, 긴 나무 장대 + 넓은 목제 촉 | 중간에 가죽 띠 | 길이가 커서 1인칭 보정 필수 |
| M-W06 | 목제 도끼 | 자루 약 3.0 + 반달형 목제 날 | 자루 끝 마디 | 날 방향이 휘두르는 방향과 일치 |

- **텍스처 팔레트:** 나무 3단(밝음/중간/어둠) + 가죽 갈색 + 가드용 짙은 나무. 아키타입 구분용 작은 포인트(예: 손잡이 끈 색)를 달리하되 색에만 의존하지 않는다.
- **체험용 임시 무기**는 같은 모델을 쓰고 컴포넌트로 "대여"만 표시한다(별도 모델 불필요).

### 2.3 공통 UI 요구

- **입력:** 마우스·키보드 기본, 키보드만으로 이동·확정 가능. 게임패드는 후순위.
- **접근성:** 색에만 의존하지 않고 아이콘·텍스트 병기, 텍스트 크기 조절, 이펙트 상세도 옵션(`fx-spec.md`) 준수.
- **다국어:** 모든 문자열은 번역 키(`ko_kr`, `en_us`)로 관리, 하드코딩 금지.
- **서버 권위:** 후보 목록·횟수·가격은 서버가 내려주는 값을 표시하고, 클라이언트 값으로 결정하지 않는다(명세 3.3장).
- **상태 복원:** UI를 닫거나 접속이 끊겨도 재접속 시 이어서 진행.
- **로딩/지연:** 서버 응답 대기 중 버튼 비활성·스피너, 실패 시 안내.
- **구현 방식 결정(미확정):** 서버 메뉴(컨테이너) 기반 vs 커스텀 화면 + 패킷. 3D 프리뷰와 카드 레이아웃은 커스텀 화면이 유리하다.
- **디자인 리소스:** 패널 9-슬라이스 배경, 버튼 3상태(기본·호버·눌림·비활성), 폰트(한글 가독성), 색 토큰(밝은/어두운 테마).

## 4. 카탈로그 확장 시 에셋 규모와 절감 전략

현재 카탈로그는 361종(아키타입 15 × 테마 23 + 고유 16)이다. 모델·텍스처를 무기마다 만들면 감당하기 어렵다.

| 전략 | 내용 | 에셋 수 |
|---|---|---|
| **아키타입 모델 재사용** | 아키타입당 **기본 모델 1개**(15), 티어·테마는 **텍스처만 교체** | 모델 15 + 텍스처 15 × (사용 테마 수) |
| **팔레트 교체** | 테마별 색 팔레트(23)를 정의하고 텍스처를 자동 생성(도구) | 팔레트 23, 텍스처 자동 생성 |
| **티어 장식 오버레이** | T3 이상은 날/가드에 장식 레이어(별도 텍스처)를 얹음 | 오버레이 소수 |
| **고유 무기 개별 제작** | 고유 16종은 개별 모델(필요 시 기본 모델 변형) | 모델 16 |
| **이펙트로 보완** | 테마 오버레이 효과(`fx-spec.md`)로 질감 차이를 표현 | fx 8종 |

- **최소 시작 구성(권장):** 아키타입 3~4개 × 테마 라인 2~3개로 시작하면 모델 3~4 + 텍스처 약 10 + 효과 세트 약 10으로 출시 가능(`weapon-catalog.md` 4장).
- 자동화: `tools/`에 팔레트 교체 스크립트를 두고 `weapons_approved.json`의 `theme`/`tier`로 텍스처를 생성하는 파이프라인을 후속 과제로 검토한다.

## 5. 제작·검수 체크리스트

### 5.1 모델

- [ ] 6종 목제 모델이 서로 **실루엣만으로 구분**된다(흑백 캡처 테스트).
- [ ] 1인칭·3인칭·GUI·바닥·액자·머리 변환이 모두 정의되고 대형 무기(대검·창)가 화면을 가리지 않는다.
- [ ] 쌍검 모델이 1인칭에서 양 자루가 보인다(오프핸드 비움 규칙, `combat-spec.md` 12.3).
- [ ] 모델·텍스처 파일명·폴더 규칙, `provenance` 기록이 있다.
- [ ] 큐브 수·텍스처 크기 상한 이내, 성능 저하가 없다(다수 플레이어 동시 표시).
- [ ] `custom_model_data` predicate로 `def_id` 모델이 정확히 선택된다.

### 5.2 UI

- [ ] 선택 화면 6종 카드·상세 패널·체험·확정·지급 흐름이 서버 검증과 함께 동작한다.
- [ ] 중복 클릭·재접속·UI 닫기 후 재개에서도 1회 발급이 유지된다(`starter-weapon-spec.md` 6장).
- [ ] 색 비의존(아이콘·텍스트 병기), 키보드 조작, 텍스트 크기, 번역 키가 적용된다.
- [ ] 공격 쿨다운 표시가 서버 쿨다운과 어긋나지 않는다(지연 시 허용 오차).
- [ ] 툴팁이 등급·귀속·공격 정의·진화 가능 여부를 정확히 표시한다.
- [ ] 에러/예외 상태 안내가 모두 정의돼 있다.

### 5.3 연습장

- [ ] 허수아비가 피해 수치를 표시하고 리셋되며 파괴되지 않는다.
- [ ] 체험 무기가 연습장 밖으로 나가면 회수된다.
- [ ] 연습장에서 나온 피해가 경제·보상·랭킹에 반영되지 않는다.

## 6. 제작 순서 (제안)
