# 시작 무기 선택 규격 v0.1

> 제안(2026-11-11): 서버 시작(최초 접속) 시 **나무 무기 후보 중 하나를 골라** 받는다.
> 연관: 명세 1.2장(플레이어 루프), 4장(계정·닉네임·직업), `weapon-catalog.md`(T0 목제·진화), `gearbridge-spec.md`(발급·귀속), `weapon-archetypes-spec.md`.
> 상태: **[제안]**. 수치와 UI 세부는 확정 전이다.

## 1. 평가: 좋은 방향이다

| 장점 | 설명 |
|---|---|
| 첫 선택이 정체성이 된다 | 플레이 스타일을 처음부터 고르게 해 몰입과 재방문 동기를 만든다 |
| 제작·조합 금지 정책과 맞다 | 무기는 서버가 발급(명세 1.1장)하므로 "첫 무기도 서버가 준다"는 일관성이 있다 |
| 진화 트리의 시작점이 생긴다 | 목제(T0) → 철/청동(T1) → … 진화 경로가 처음부터 열린다 |
| 비용이 작다 | 목제 모델 6~8종만 있으면 되고 신규 시스템이 거의 없다(발급은 `guard.identity` 재사용) |

**주의점:** 모든 아키타입을 첫 선택지에 넣으면 선택 부담이 크고 입문자가 불리한 선택을 할 수 있다. 입문 친화적인 6종만 제시하고 나머지는 상점·진화로 해금한다.

## 2. 흐름

```text
최초 접속 → 닉네임 지정 → 직업 선택 → 시작 무기 선택 → (연습장에서 체험 가능) → 확정 → 인벤토리/보관함 지급
```

- 순서: 닉네임 → 직업 → 무기. 직업은 경제 루프, 무기는 전투 루프이므로 서로 독립이고 무기를 나중에 두는 편이 설명이 쉽다. `[순서는 UI 설계(G5)에서 확정]`
- **체험:** 선택 전에 연습장(허수아비)에서 후보 6종을 시험한다. 체험용 무기는 임시 대여이며 연습장을 떠나면 회수한다.
- **재진입:** 닉네임·무기 UI를 도중에 닫았다면 재접속 시 이어서 선택한다(명세 4.1장 닉네임과 같은 규칙).

## 3. 후보와 데이터

`data/weapon_catalog/starter.json` 기준.

| 항목 | 값(제안) |
|---|---|
| 후보 아키타입 | 한손검, 단검, 쌍검, 대검, 창, 도끼 (6종) |
| 테마 | 목제(`wood`, T0) — 15개 아키타입 모두 `*_wood` 정의가 카탈로그에 있고, 시작 후보는 6종만 노출 |
| 티어 배율 | T0 ×0.7(시작 무기는 철 무기보다 약함) |
| 귀속 | 획득 시 귀속(`bind_on_acquire`), 거래 불가 |
| 계정당 선택 횟수 | 1회 |
| 무료 교체 | 선택 후 24시간 안에 1회(이전 무기 회수, 새 `serial` 발급) |
| 추가 해금 | 나머지 9개 아키타입은 상점(Coin 소각)·진화·보상으로 해금 |

- **진화:** 목제(T0) → 철(T1) 또는 청동(T1)으로 분기 진화한다(`themes.json`). 첫 진화는 저렴한 Coin 비용 + 기본 재료로 열어 두어 초반 성장 곡선을 만든다.
- 시작 무기 비용: **무료**(Coin 발행 없음). 시작 무기로 판매·거래할 수 없으므로 재화 생성 경로가 아니다.

## 4. 서버 처리 (멱등성·보안)

```text
CLAIM_STARTER(player_uuid, archetype, request_id):
  assert archetype in starter.offer_archetypes
  if request_id already processed: return saved result
  BEGIN TRANSACTION
    lock(starter_claims[player_uuid])
    assert not claimed (또는 free_swap 조건 충족)
    stack = GearBridge.issue(def_id = archetype + "_wood", owner = player, source_event_id = request_id)
    insert starter_claims(player_uuid, archetype, claimed_at, request_id, swap_used)
    insert outbox(op = deliver_to_inventory_or_mailbox)
  COMMIT
  deliver; emit StarterWeaponClaimed
```

| 데이터 | 필드 |
|---|---|
| `starter_claims` | `uuid PK, def_id, serial, claimed_at, swap_used, request_id UNIQUE` |

- 인벤토리 가득 참·서버 종료 시에도 **1회 발급 ↔ 1개 지급**(보관함으로 이전). 중복 클릭·재접속에 안전해야 한다.
- 교체는 이전 `serial`을 `destroyed(cause=swap)`로 처리하고 새로 발급한다(복제 방지).
- **다중 계정 어뷰징:** 시작 무기는 귀속·약함이라 이득이 작지만, 신규 계정이 시작 무기로 초반 재화를 파밍하는 경로가 생기지 않게 직업 수익 시스템의 반복 입력 제한(명세 5.5장)을 유지한다.

## 5. 연출·UI

> 모델·UI·아이콘·소리 요구 목록은 `asset-requirements.md`에 정리했다.

- 선택 화면: 6종의 아이콘, 역할 한 줄(`weapon-archetypes-spec.md` 6장 강·약점), 간단한 스탯 막대(공격 속도, 사거리, 범위), "체험하기" 버튼.
- 선택 확정 시 짧은 연출(`fx-spec.md`의 `ENHANCE_SUCCESS`와 같은 계열 파티클·소리 재사용) + 안내(진화 경로, 상점 안내).
- 접근성: 색에만 의존하지 않고 텍스트·아이콘으로 구분한다.

## 6. 검수 항목

- [ ] 첫 접속에서 시작 무기를 1회만 받을 수 있고, 두 번째 요청은 거부된다.
- [ ] 중복 클릭·재접속·인벤토리 가득 참·서버 종료에서도 1회 발급, 1개 지급.
- [ ] 무료 교체가 24시간 안에 1회만 되고, 이전 무기가 회수되며 새 `serial`이 발급된다.
- [ ] 후보 6종 외 아키타입은 선택할 수 없다(서버 검증).
- [ ] 체험용 임시 무기를 가지고 연습장을 떠날 수 없다.
- [ ] 시작 무기가 목제 → 철/청동 진화 경로로 이어진다.
- [ ] UI를 닫고 재접속하면 이어서 선택한다.

## 7. 미확정

1. 후보 6종을 확정할지(다른 아키타입을 넣을지)와 노출 개수
2. 선택 순서(닉네임 → 직업 → 무기)와 연습장 위치
3. 무료 교체 시간·횟수, 이후 교체 비용(Coin 소각)
4. 목제 → 철/청동 진화 비용과 조건
5. 시작 무기 모델 제작 범위(후보 6종 목제 모델)
6. 시작 무기를 장비 도감에 포함할지(도감 최초 달성 보상 중복 방지와 함께 결정)
