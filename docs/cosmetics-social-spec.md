# 치장·소셜 1순위 규격 v0.1

> 범위: 칭호 조건 다양화 / 이름 꾸미기 / 프로필 카드 / 서버 알림·명예의 전당 (4개)
> 위치: 명세서 15장 `social/` 모듈 + 신규 `cosmetics/`. 기존 명세 6.3(도감)·6.4(칭호)·13장(외형·문패)·12.3장(감사)을 확장한다.
> 전제: 이 서버는 **현금 과금이 없고 Coin만 사용**한다. 아래 구상은 법적 쟁점이 아니라 운영·밸런스 문제로만 다룬다.
> 주의: 이벤트·API 이름은 후보이며 NeoForge 1.21.1 실제 코드로 확인한다.

## 0. 공통 원칙

1. **전투 판정 불변**: 칭호·이름 꾸미기·프로필·랭킹은 공격력·명중 범위·이동에 영향이 없다.
2. **획득 경로**: 뽑기 외에 직접 구매 또는 업적으로 얻는 경로를 하나 이상 둔다.
3. **삭제 대신 비활성화**: 지급된 칭호·치장은 회수하지 않고 `active=false`로 감사 기록을 유지한다(6.4장 승계).
4. **랭킹 보상은 칭호·치장만**: Coin을 걸지 않는다(어뷰징 방지, 9.4장 좋아요 보상 금지와 같은 이유).
5. **서버 권위**: 조건 판정·구매·랭킹 기록은 서버가 계산한다. 클라이언트는 표시와 요청만 한다.
6. **멱등성**: 지급·구매·랭킹 등록은 `event_id`로 한 번만 처리한다(14.2장).
7. 표시 문자열은 4.1장 닉네임 규칙(금칙어·서식 제어 문자·길이)을 따른다.
8. **검 외형·이펙트 치장(2026-11-11 방침):** 검 외형은 장비 백엔드에 따라 구현한다 — 바닐라 백엔드는 우리 컴포넌트·커스텀 모델 지정, LR 백엔드는 `DisplayId`. 연출 치장(궤적 색, 타격 효과 변형)은 `fx-spec.md`의 **fx 스킨**으로 처리하며 스탯·도감 키에 영향을 주지 않는다. 구매·보유는 이름 스타일과 같은 구조다.

## 1. 칭호 조건 시스템

### 1.1 칭호 정의 (6.4장 확장)

```text
title = { id, key, name, desc, rarity, color, prefix_or_suffix,
          category, hidden, season_id|null, set_id|null,
          grant_type: auto|manual|shop, shop_price|null,
          active, created_by, created_at }
```

- `category`: 도감 / 직업 / 보스 / 강화 / 시즌 / 이벤트 / 운영.
- `hidden`: 조건 공개 여부. 숨김 칭호는 획득 전 이름·조건을 목록에서 감춘다.
- `grant_type=manual`은 운영자 수동 부여(기존 6.4장 기능 유지).

### 1.2 조건 유형

| 유형 | 조건 예시 | 입력 이벤트(15장) |
|---|---|---|
| 도감 | 검 도감 N% 달성, 특정 단계 최초 달성 | `CollectionUnlocked`, `GearEnhanced` |
| 직업 | 직업 레벨 N, 직업별 누적 납품 M | `JobItemProduced`, `ContractCompleted` |
| 보스 | 보스 X 최초 클리어, 난이도별 클리어, 솔로 클리어 | `BossDefeated` |
| 강화 | 강화 N단계 도달(보유/최초), 누적 강화 시도 | `GearEnhanced`, `GearDestroyed` |
| 시즌 | 시즌 중 활동 기준 충족 | 시즌 집계 |
| 이벤트 | 대회 입상·참가 | 이벤트 시스템(추후) |

- 조건식은 **데이터(JSON)로 정의**하고 AND/OR 조합을 허용한다. 서버 재시작 없이 핫리로드한다.
- 같은 조건이 반복 달성돼도 `(player_uuid, title_id)` 유니크로 한 번만 지급한다.
- **소급 평가**: 새 칭호를 추가하거나 조건을 바꿀 때, 과거 기록(`collections`, `boss_clears` 등)으로 대상 플레이어를 일괄 평가하는 작업을 제공한다. 실행 전 대상 인원 미리보기를 보여준다.
- 파괴로 장비가 사라져도 이미 획득한 칭호는 유지한다(6.3장 승계).

### 1.3 칭호 세트

- `set_id`로 묶인 칭호를 모두 보유하면 **상위 칭호**를 지급한다(예: 직업 4종 만렙 → "만능 생활인").
- 세트 진행도를 UI에 표시한다(`3/5`).

### 1.4 장착·표시

- 기본: **칭호 1개 장착**, 표시 순서 `[칭호] 닉네임`(6.4장). 장착 슬롯 수는 설정값.
- 장착 변경에는 쿨타임을 둘 수 있다(채팅 도배 방지, 설정값).

### 1.5 데이터

| 테이블 | 주요 필드 |
|---|---|
| `titles` | 1.1의 필드 |
| `title_conditions` | `title_id, expr_json, version` |
| `player_titles` | `uuid, title_id, granted_at, reason, source_event_id UNIQUE, equipped` |
| `title_sets` | `set_id, member_title_ids, reward_title_id` |

## 2. 이름 꾸미기

### 2.1 꾸미기 종류

| 종류 | 내용 | 비고 |
|---|---|---|
| 이름 색 | 단색 | 서버가 허용한 팔레트만 |
| 그라데이션 | 두 색 이상 보간 | 닉네임 길이 제한 내에서 |
| 테두리/장식 | `「 」`, `★`, `◆` 등 장식 문자 | 허용 목록 방식 |
| 칭호 색 | 칭호 글자색 | 칭호 자체 색과 우선순위 정의 필요 |

- 플레이어가 임의의 서식 코드나 색 코드를 입력하지 못한다. **서버가 정의한 스타일 ID만** 선택한다(채팅 악용 색 코드 방지, 6.4장).
- **가독성 검사**: 어두운 배경·밝은 배경 모두에서 읽을 수 있는 대비 기준을 팔레트 등록 시 통과해야 한다.

### 2.2 획득·구매

- 구매: **Coin 소각**(원장 `reason=cosmetic_purchase`, 7.1장). 한정 스타일은 업적·이벤트·시즌으로 획득.
- 구매는 원자적으로 처리(차감 실패 시 지급 금지, 지급 실패 시 롤백 — 7.3장). 보유 스타일 중복 구매 차단.
- 가격과 해금 경로는 데이터로 관리하며 변경 이력을 남긴다.

### 2.3 적용 위치

채팅, 탭 목록, 머리 위 이름표, 거래소·게시판, 랭킹·프로필 카드, 수배 로그 표시값(스냅샷).

- 머리 위 이름표와 탭 목록의 색/그라데이션 표시는 바닐라 텍스트 컴포넌트로 가능한지 **C0에서 확인**한다. 클라이언트 모드가 필요하면 범위를 줄인다(1순위는 클라이언트 모드 불필요를 목표로 함).

### 2.4 데이터

| 테이블 | 주요 필드 |
|---|---|
| `name_styles` | `style_id, kind, definition_json, price, unlock_type, active` |
| `player_name_styles` | `uuid, style_id, acquired_at, source_event_id UNIQUE` |
| `player_equipped_style` | `uuid, style_id` |

## 3. 프로필 카드

### 3.1 표시 항목

- 닉네임·장착 칭호·이름 스타일, 가입일, 마지막 접속(공개 설정에 따름)
- 활성 직업과 레벨, 직업별 레벨 요약
- 도감 수집률(검/방어구/활/기타), 최고 강화 단계, 보스 클리어 수
- **대표 장비**: 플레이어가 지정한 장비 1~3개의 **스냅샷**(이름·강화 단계·강화자). 실물 아이템과 연결하지 않으므로 파괴·거래 후에도 업적 기록으로 남는다(실물 보유 여부와 구분 표시).
- 대표 칭호 목록(최대 N개)과 세트 진행도
- 소개 문구(짧은 텍스트, 금칙어 검사)

### 3.2 접근

- 명령 `/프로필 [닉네임]`, 메인 메뉴 `내 정보`, 다른 플레이어 상호작용(우클릭 등, 후보).
- 공개 설정: `공개 / 친구만 / 비공개`(항목별로 세분화할지는 미확정).
- 조회는 읽기 전용이고 서버가 집계한다. 자주 조회되는 값은 캐시하고 변경 시 무효화한다.

### 3.3 데이터

| 테이블 | 주요 필드 |
|---|---|
| `profile_settings` | `uuid, visibility, bio, showcase_serials_json, updated_at` |

- 집계 값(도감률·클리어 수 등)은 기존 테이블에서 계산하며 프로필에 **중복 저장하지 않는다**(정합성).

## 4. 서버 알림과 명예의 전당

### 4.1 서버 알림

| 이벤트 | 기본 알림 | 비고 |
|---|---|---|
| 높은 강화 단계 **성공** | 전체 공지 | 임계 단계는 설정(예: 최상위 N개 단계) |
| 보스 최초 클리어(서버 최초/개인 최초) | 전체 공지(서버 최초) / 본인 알림(개인 최초) | |
| 보스 최단 기록 경신 | 전체 공지 | 4.2의 랭킹과 연동 |
| 칭호 세트 완성·희귀 칭호 획득 | 선택 공지 | `rarity` 기준 |

- **강화 파괴는 전체 공지하지 않는다**(조롱·괴롭힘 방지). 본인에게만 알림. 공개 여부는 운영 설정으로 바꿀 수 있다.
- 알림에는 `쿨다운`과 `중복 방지`(같은 플레이어·같은 이벤트)를 둔다. 플레이어별 **알림 옵트아웃**(내 알림 숨김)을 제공한다.
- 알림 문구는 템플릿 데이터로 관리하고, 닉네임은 표시명 + 이름 스타일을 적용한다.

### 4.2 랭킹(명예의 전당)

| 랭킹 | 기준 | 어뷰징 고려 |
|---|---|---|
| 보스 최단 클리어 | `boss_id × 난이도 × 파티 크기`별 분리, 서버 계측 시간 | 파티 크기를 분리하지 않으면 솔로와 파티 비교가 불공정. 소환 취소·자살·접속 종료로 얻은 기록은 무효 |
| 직업별 주간 랭킹 | **직업 XP 획득량** 또는 **납품 수량**(품목 가격 영향 없는 지표) | 판매 Coin 기준은 시세·AFK 영향이 커서 지양. 5.5장의 반복 입력 제한이 적용된 값만 집계 |
| 도감 수집률 | 도감 수집 완료율 | 마일스톤 보상 중복 지급과 무관한 표시 전용 |

- **보상은 칭호와 치장만.** 주간 1~3위·상위 N% 등으로 데이터화하고, 보상 지급은 `reward_event_id UNIQUE`로 1회만 처리한다.
- 주간/시즌 단위로 초기화하되 **과거 순위는 아카이브**해 칭호 근거로 남긴다.
- 의심 기록(복제·버그·권한 우회)은 운영자가 `invalidated`로 표시하고 순위를 재계산한다. 감사 로그를 남긴다.
- 랭킹 노출은 프로필 설정과 별개로, 순위에 오른 플레이어에게 공개를 옵트아웃할 수 있게 할지 **미확정**.

### 4.3 데이터

| 테이블 | 주요 필드 |
|---|---|
| `leaderboards` | `board_id, type, scope(boss/job/collection), period, rules_json, reward_rules_json` |
| `leaderboard_entries` | `board_id, period_key, uuid, score, party_size, recorded_at, invalidated` |
| `announcements` | `ann_id, type, template, trigger_json, cooldown_sec, active` |
| `announcement_log` | `ann_id, event_id UNIQUE, target, sent_at` |

## 5. 코어 모드 연동 지점

| 필요 기능 | 담당 | 비고 |
|---|---|---|
| 이벤트 버스(`GearEnhanced`, `BossDefeated`, `JobItemProduced` 등) | 코어 `platform` | 칭호 조건·알림·랭킹의 공통 입력 |
| 원장·멱등성 | 코어 `persistence` | 구매·보상 1회 처리 |
| 이름 렌더링(채팅/탭/이름표) | 코어 `cosmetics` | C0에서 가능 범위 검증 |
| 관리자 GUI/명령 | 코어 `admin` | 칭호·스타일·랭킹 CRUD, 소급 평가, 무효 처리 |
| 감사 로그 | 코어 `admin_audit` | 운영자 변경 이력 |

- 전제 모듈(이벤트 버스, 원장, DB)이 생기기 전에는 구현할 수 없으므로 **코어 단계 C0~C3 이후** 착수한다. 단, 데이터 정의와 UI 와이어프레임(G5)은 먼저 진행할 수 있다.

## 6. 구현 순서 (제안)

| 단계 | 내용 | 완료 조건 |
|---|---|---|
| S1 | 칭호 정의·조건 엔진(도감/직업/보스 조건부터), 장착, 소급 평가 | 같은 조건 반복 달성 시 지급 1회, 소급 평가 미리보기 |
| S2 | 이름 스타일 카탈로그·구매·적용(채팅→탭→이름표 순) | 구매 원자성, 서식 코드 주입 불가 |
| S3 | 프로필 카드와 공개 설정 | 비공개 항목이 노출되지 않음 |
| S4 | 서버 알림 | 쿨다운·옵트아웃·중복 방지 |
| S5 | 랭킹(보스 → 직업 주간 → 도감), 보상 지급, 아카이브 | 무효 처리 후 재계산, 보상 1회 |

## 7. 검수 시나리오

- [ ] 칭호 조건을 반복 달성해도 칭호가 1회만 지급된다.
- [ ] 칭호 조건 추가 후 소급 평가가 올바른 대상에게만 지급되고 미리보기와 일치한다.
- [ ] 장비가 파괴돼도 획득한 칭호·프로필 대표 장비 스냅샷이 유지된다.
- [ ] 플레이어가 임의 서식/색 코드를 입력할 수 없고, 허용된 스타일만 적용된다.
- [ ] 스타일 구매 중 중복 클릭·재접속이 있어도 Coin 1회 차감 ↔ 지급 1회.
- [ ] 이름 스타일이 채팅·탭·이름표·거래소·랭킹에 일관되게 표시된다.
- [ ] 프로필 공개 설정(비공개/친구만)이 서버에서 강제된다.
- [ ] 강화 파괴가 전체 공지되지 않고, 옵트아웃한 플레이어에게 알림이 가지 않는다.
- [ ] 보스 최단 기록이 파티 크기·난이도별로 분리되고, 소환 취소·자살·접속 종료 기록은 무효 처리된다.
- [ ] 랭킹 보상이 `reward_event_id`로 1회만 지급되고 Coin은 지급되지 않는다.
- [ ] 무효 처리 시 순위가 재계산되고 감사 로그가 남는다.

## 8. 미확정 항목

1. 칭호 동시 장착 수, 장착 변경 쿨타임
2. 이름 스타일 종류 범위(그라데이션 지원 여부), 허용 장식 문자 목록, 가격
3. 프로필 공개 설정의 세분화(항목별 vs 전체)와 소개 문구 허용 여부
4. 알림 임계값(강화 단계 기준), 전체 공지 빈도 상한
5. 랭킹 집계 지표 확정(직업 XP vs 납품 수량)과 보상 구조(상위 N명 vs 상위 %)
6. 랭킹 노출 옵트아웃 허용 여부
7. 머리 위 이름표·탭 목록에서 바닐라 컴포넌트만으로 스타일 구현이 가능한지(C0 확인)
8. 시즌 길이와 시즌 칭호·치장의 복각 정책
