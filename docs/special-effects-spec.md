# 고등급 강화 무기 특수 효과 규격 v0.1

> 질문: 고등급 강화 무기에 특수 효과를 넣을 방법이 있는가? → **있다.** 서버 권위 전투 모듈(`combat-spec.md`)의 피해 파이프라인에 **특수 효과(proc) 훅**을 붙이는 방식이다. 시각 연출(`fx-spec.md`)과 **게임플레이 효과**를 구분해서 설계한다.
> 연관: `combat-spec.md`(피해 파이프라인), `gearbridge-spec.md`(강화 단계), `fx-spec.md`, `weapon-catalog.md`(테마·티어), `G3-economy-simulation-sheet.md`(밸런스).
> 상태: **[제안]**. 수치는 모두 G3·실측으로 확정한다.

## 1. 두 종류를 구분한다

| 종류 | 내용 | 판정 영향 | 구현 위치 |
|---|---|---|---|
| **시각 효과** | 오라, 궤적, 타격 불꽃 (`fx-spec.md`) | 없음 | `fx` 모듈 |
| **특수 효과(게임플레이)** | 상태이상, 연쇄 피해, 폭발, 회복 등 | **있음** (밸런스 대상) | `combat`의 피해 파이프라인 훅 + `fx`로 연출 |

- 특수 효과는 **서버가 결정**한다(서버 난수, 서버 쿨다운). 클라이언트는 표시만 한다.
- 특수 효과가 발동하면 `fx`에 `PROC` 트리거를 보내 별도 연출을 낸다.

## 2. 구조

```text
combat 피해 파이프라인
  타격 확정(ValidatedMeleeHit) → [on_hit 훅] → 피해 적용 → [on_crit / on_kill / combo_finisher 훅]
                                    │
                         SpecialEffectEngine
                           ├ 해금 확인: 무기 정의 + 티어 + 강화 단계
                           ├ 조건·확률·내부 쿨다운 평가(서버 RNG)
                           ├ 효과 실행(상태이상 / 연쇄 / 폭발 / 회복 ...)
                           └ PROC 이벤트 발행 → fx
```

- **효과 정의는 데이터(JSON)** 이고 무기는 효과 ID와 해금 조건만 참조한다. 스택에는 효과를 저장하지 않고, 서버가 `def_id + tier + enhance_level`로 **매번 계산**한다(복제·변조에 안전).

## 3. 효과 정의 (데이터)

```yaml
special_effect:
  id: "fire_burn"
  trigger: on_hit                    # on_hit | on_crit | on_kill | combo_finisher | right_attack | every_n_hits
  chance: 0.25                       # 서버 RNG (every_n_hits면 n)
  internal_cooldown_ticks: 40        # 같은 대상/같은 효과 재발동 간격
  target: victim                     # victim | nearby_enemies | self
  actions:
    - { type: apply_status, status: "burn", duration_ticks: 60, tick_damage_ratio: 0.10 }   # 공격 피해의 10%/틱 간격
  can_proc_from_proc: false          # 효과가 만든 피해가 다른 효과를 발동시키지 않음
  boss_scale: 0.5                    # 보스에게는 효과 강도 감소
fx: { on_proc: "fx_proc_fire_burn" }
```

### 3.1 효과 종류(액션)

| 액션 | 내용 | 비고 |
|---|---|---|
| `apply_status` | 화상(지속 피해), 둔화, 중독, 빙결(짧은 이동 불가), 약화 | 바닐라 상태 효과 또는 자체 상태 |
| `chain_damage` | 대상 주변 최대 N마리에 연쇄 피해(원 피해의 비율) | 번개 계열 |
| `aoe_burst` | 대상 위치 폭발(반경, 피해 비율) | 불꽃, 대검 마무리 |
| `lifesteal` | 입힌 피해의 일부 회복 | 성광/그림자 계열, 상한 필요 |
| `execute` | 대상 체력이 임계 이하면 추가 피해 | 도끼 계열, 보스 제한 |
| `knockback_boost`, `stun_short` | 넉백 증가·짧은 경직 | 해머·메이스 |
| `mark` | 표식을 남기고 다음 타격이 추가 피해 | 단검·레이피어 |

## 4. 해금 규칙 (강화 단계와 티어)

특수 효과를 **강화 보상**으로 삼는다. 강화가 서버의 핵심 콘텐츠이므로 높은 강화 단계가 곧 목표가 된다.

| 티어 | 해금 슬롯(제안) |
|---|---|
| T0~T2 | 특수 효과 없음(시각 오라만, `enhance_level ≥ 5`) |
| T3 (희귀) | +10에 효과 1개 |
| T4 (영웅) | +10 효과 1, +15 효과 2 |
| T5 (전설) | +5 효과 1, +10 효과 2, +15 효과 3, +20 **각성 효과**(고유 연출) |

- 해금은 **현재 `enhance_level` 기준**이다. 강화 실패로 단계가 유지되는 것은 문제없지만 **파괴되면 효과도 함께 사라진다**(실물 소멸). 진화 시 `carry_over_ratio`(`gearbridge-spec.md` 13장)에 따라 단계가 이월되므로 효과도 이월된 단계에서 재평가된다.
- 효과 강도는 같은 효과 안에서 **단계에 따라 점진 증가**할 수 있다(예: +10 화상 3초, +15에서 4초).

## 5. 테마별 기본 효과 팩 (제안)

카탈로그의 테마 라인(`weapon-catalog.md` 2.2)을 효과 팩과 1:1로 묶어 346종을 새로 쓰지 않고 **테마당 효과 2~3개**만 만든다.

| 테마(라인) | 효과 1 | 효과 2 | 각성(T5) |
|---|---|---|---|
| 불꽃 → 용암 → 화룡 | 타격 시 화상(지속 피해) | 마무리 타격 폭발 | 화염 폭풍(주변 지속 폭발) |
| 서리 → 빙하 → 극한 | 둔화 | 3연속 명중 시 짧은 빙결 | 극한의 파동(주변 둔화 + 빙결) |
| 번개 → 폭풍 → 천뢰 | 연쇄 번개(주변 최대 2마리) | 치명타 시 추가 번개 | 낙뢰(대상 위치 광역 번개) |
| 성광 → 천상 → 신성 | 처치 시 소량 회복 | 아군 근처 버프(파티) | 심판(표식 대상에 추가 피해) |
| 맹독 → 부식 → 역병 | 중독 누적(스택) | 방어력 감소 표식 | 역병 확산(처치 시 주변 전이) |
| 그림자 → 암흑 → 심연 | 후방 공격 시 추가 피해 | 표식 후 추가 타격 | 그림자 분신(짧은 추가 타격) |

- 고유 무기 16종(`uniques.json`)은 각자 **고유 효과 1개**를 갖는다(예: 일월: 치명타 시 "해와 달" 이중 베기).
- 아키타입의 `crit_multiplier`, `backstab_multiplier`와는 **별개**이고 합산 상한을 둔다(5.2).

## 6. 밸런스 가드레일

| 규칙 | 내용 |
|---|---|
| 효과 DPS 예산 | 특수 효과의 **기대 추가 DPS는 기본 DPS의 최대 15%**(T5 +20, 전체 효과 합) [제안]. G3에서 `기본 DPS + 효과 기대 DPS`로 계산 |
| 내부 쿨다운 | 효과마다 같은 대상 재발동 간격을 둔다(상태이상 도배 방지) |
| 효과 연쇄 금지 | `can_proc_from_proc: false` 기본. 효과가 만든 피해는 다른 효과를 발동시키지 않음 |
| 보스 감쇠 | 보스에는 `boss_scale`로 효과 강도를 줄이고 제어 효과(빙결·경직)는 무효 또는 짧게 |
| 대상 수 상한 | 연쇄·폭발은 최대 대상 수·반경 제한(성능 예산 연동) |
| 회복 상한 | `lifesteal`은 초당 회복량 상한 |
| PvP | 기본 끔(`combat-spec.md` 11장). 켤 때는 제어·회복 효과를 PvP 전용 수치로 낮춘다 |
| 서버 RNG | 확률 효과는 서버가 판정. 시드·결과를 로그에 남겨 감사 가능 |

### 6.1 확률 대신 결정적 발동 옵션

- `every_n_hits`(N번째 명중마다 발동)나 마무리 타격 고정 발동은 **예측 가능**하고 검증이 쉽다. 확률형은 분산이 크므로 고강화 구간은 결정적 발동을 우선한다.

## 7. 연출·UI·도감 연동

- **연출:** 효과 발동마다 `PROC` 트리거를 `fx`로 보내 파티클·소리·화면 흔들림을 낸다(예산은 `fx-spec.md` 4장). 해금된 효과 수에 따라 오라가 강해진다.
- **툴팁/UI:** 무기 툴팁과 강화 UI에 "+10: 화상 25%", 잠금 표시(🔒 +15), 현재 활성 효과를 보여준다. 확률과 수치는 공개한다.
- **도감·칭호:** "특수 효과 N개 해금", "전설 무기 각성" 같은 마일스톤을 도감 보상·칭호 조건으로 연결한다(`cosmetics-social-spec.md` 1장).
- **서버 알림:** 전설 각성 효과 최초 해금은 서버 공지 후보(옵트아웃 존중).

## 8. GearBridge·데이터 연동

- `gear_defs`에 `effects: [{id, unlock_level}]`를 두고, 테마 효과 팩에서 기본값을 상속한다(생성기가 테마별 팩을 붙임). `weapons.json` 생성기에 `effect_pack` 필드를 추가할 수 있다(후속).
- 강화 결과 확정 후 `GearEnhanced` 이벤트가 오면 **효과 해금 알림**을 `fx`/UI로 보낸다.
- 효과 해금은 DB에 저장하지 않고 단계에서 파생한다(정본: `enhance_level`).

## 9. 구현 단계 (제안)

| 단계 | 내용 | 완료 조건 |
|---|---|---|
| SE0 | `SpecialEffectEngine`, 효과 정의 로더(핫리로드), `on_hit` 훅과 `apply_status`(화상·둔화) | 서버 RNG·내부 쿨다운 동작, 로그 |

| SE3 | 고유 무기 효과 16종, 각성 효과 연출 | 연출 예산 통과 |
| SE4 | G3 시뮬레이션: 효과 포함 DPS 편차, 보스 클리어 시간 | 가드레일 15% 이내 |

## 10. 검수 항목

- [ ] 효과가 서버 RNG·내부 쿨다운으로만 발동하고, 클라이언트가 발동을 요청하거나 변조할 수 없다.
- [ ] 효과가 만든 피해가 다른 효과를 연쇄 발동시키지 않는다.
- [ ] 강화 단계가 오르내리거나 파괴·진화될 때 효과가 정확히 갱신된다(스택에 효과가 저장되지 않음).
- [ ] 보스에 `boss_scale`이 적용되고 제어 효과가 제한된다.
- [ ] 연쇄·폭발이 대상 수·반경 상한과 파티클 예산을 지킨다.
- [ ] 효과 포함 기대 DPS가 가드레일(+15%) 안에 있다(G3).
- [ ] 툴팁에 확률·수치·해금 단계가 공개된다.
- [ ] 같은 이벤트가 중복 도착해도 효과가 1회만 처리된다(`event_id` 멱등성).

## 11. 미확정

1. 해금 단계(+5/+10/+15/+20)와 티어별 슬롯 수
2. 효과 DPS 예산 15%의 적정 값(G3)
3. 확률형 vs 결정적 발동 비율, 보스 감쇠 계수
4. 자체 상태이상(빙결 등)을 바닐라 상태 효과로 표현할지 별도 구현할지
5. 파티 버프·표식 같은 협동 효과의 도입 시기
6. PvP 구역 효과 수치
7. 효과 팩을 생성기(`weapons.json`)에 포함할 시점

## 12. 효과 팩 수치 (G3 시트 기준, 2026-11-11)

`data/g3/G3-economy-simulation.xlsx`의 **Effect_Packs** 시트에서 계산한 초깃값이다. 모든 수치는 [제안]이며 실측으로 교체한다. 시트의 입력(파란 칸)을 바꾸면 티어별 DPS 비중과 Dashboard 판정이 자동으로 다시 계산된다.

### 12.1 계산 방식

```text
효과 비중 = 초당 발동 수 × 발동당 피해(타격 환산) × 유효 대상 수 ÷ 초당 타격 수
```

- **타격 환산 1.0** = 평균 1회 타격 피해. 유틸·회복은 피해 환산 0이다(체감은 연출·상태 효과가 만든다).
- **속도 클래스 3종**으로 평가하고 최댓값을 쓴다: 느림(대검, 초당 0.80타), 중간(한손검, 1.82타), 빠름(단검, 3.00타).
- **발동 수**: `chance`는 `min(초당 타격 × 확률, 1/내부 쿨다운)`, `every_n`은 `초당 타격 ÷ N`, `periodic`은 `1/주기`, `finisher`는 `1/(콤보 사이클 × 사이클 수)`, `crit`는 `초당 타격 × 치명타 비율(10%) × 확률`.
- **유효 대상 수** = 1 + (대상 수 − 1) × 광역 비율(40%, 그룹 전투 비중).
- **티어 배율**: T3 ×1.00, T4 ×1.15, T5 ×1.30(상위 티어일수록 효과 강도가 오른다).
- **해금**: T3 = 슬롯 1, T4 = 슬롯 1~2, T5 = 슬롯 1~4(각성 포함).

### 12.4 해석과 설계 시사점

- **상한(15%) 안에서 전설 팩이 14%대**까지 올라가 예산을 거의 소진한다. 효과를 더 넣으려면 기존 효과의 발동당 피해를 낮춰야 한다.
- **빈도가 높은 효과는 발동당 피해가 작아질 수밖에 없다**(예: 화염 화상은 10%에 0.35 타격). 체감은 낮은 확률·큰 연출(불길 전이, 그림자 베기)과 상태 효과가 만든다.
- **서리·성광 팩은 피해 비중이 낮다**(유틸·회복 중심). 이 팩들은 피해 대신 군중 제어·생존 가치를 주는 방향이므로, 피해 외 가치를 별도로 평가해야 불리하지 않다(서리 T3 0%, 성광 T3·T4 0%는 해금 효과가 유틸이기 때문).
- **빠른 무기는 확률형 효과의 내부 쿨다운에 걸려 비중이 정체**된다(화염 화상: 느림/중간/빠름 모두 3.5% 부근). 쿨다운은 속도 클래스 간 격차를 줄이는 안전장치로 작동한다.
- 시트에 반영하지 않은 것: 유틸·회복의 가치 환산, 보스 감쇠(`boss_scale`), 효과 연쇄 금지 효과, 연출 비용.

시트에서 팩·효과를 수정하는 방법: `Effect_Packs`의 파란 칸(파라미터, 쿨다운, 발동당 피해, 대상 수)을 바꾸고 `Weapons_DPS` 티어 표와 `Dashboard`의 "특수 효과 DPS 비중" 판정을 확인한다.
